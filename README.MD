## 港口作业调度看板解决什么问题？

面向港口物流，围绕“泊位、车辆、堆场资源分配与作业状态追踪”提供可操作的演示系统。当前交付状态：**已完成中台功能验收；用于业务演示，未完成生产部署验收**。

## 系统架构

```text
浏览器页面 → JavaScript 校验与业务计算 → localStorage
浏览器页面 ← 列表 / 指标 / CSV ← 当前浏览器中的演示记录
```

cockpit 用于 AI 开发过程，不是此系统运行的必需服务。本系统没有因为使用 AI 开发而自动接入运行时大模型。

## 本地运行

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

打开 http://127.0.0.1:8000/index.html 。无需构建或后端依赖，也可直接打开 index.html；建议固定 HTTP 地址，避免浏览器存储来源变化。

## 操作与业务规则

## 操作步骤

1. 点击「新增作业任务」，输入虚构编号（如 `ZY-010`）、名称、正整数箱量、入场货位、排班开始与结束时间。
2. 在任务行点击「派发」，指定空闲泊位、车辆，点击「保存」。成功后立即更新占用统计及货位预留。
3. 点击「开始执行」，再点击「完成作业」。完成时泊位、车辆释放，预留箱量转入该货位现有库存，完成统计增加。
4. 切换泊位、堆场、车辆标签，可新增或编辑资源；任务仅在待派发状态可编辑。编号创建后不可修改。
5. 通过关键词及状态组合筛选，点击「导出当前 CSV」下载当前台账匹配记录。泊位排班在泊位台账中显示，具体起止时间也保存在任务 CSV 中。
6. 点击「重置演示」，取消则保留数据，确认后恢复初始样例；只影响本应用的 localStorage 键。

建议验收示例：新增 `ZY-010`，入场货位 `CW-002`、箱量 9、时间 2026-09-28 08:00 至 09:00；派发 `BW-002` 与 `JC-002`，执行并完成后，该货位库存由 20 增至 29，泊位及车辆恢复空闲。

## 真实业务规则

- 状态严格为 `待派发 → 已派发 → 执行中 → 已完成`。禁止跳转、重复派发、重复完成入库；已派发及历史任务不可编辑。
- 派发时同时检查泊位、车辆空闲与堆场剩余容量。任何检查失败，所有资源及任务数据均不改变。
- 排班使用 `[开始, 结束)` 半开区间；开始必须早于结束。任一相同泊位或车辆排班重叠即拒绝，已完成历史排班也参与冲突检查；相邻时间段可以接续。
- 派发后的资源即使排班时间尚未到达，也立即占用，直至手工完成。不会按时钟自动切换状态，不支持一个资源预派多个未来任务。
- 堆场 `剩余 = 总容量 − 现有库存 − 已派发/执行中任务预留`。完成将预留转库存，剩余容量不凭空增加。编辑货位视为人工盘点，不得侵占任务预留。
- 初始示例含一个执行中任务，两项待派发任务。示例日期固定，便于复现，不代表现场数据。
- “实时”仅指用户操作后同步重算；没有 AI 算法、真实硬件、定位、外部接口或调度优化服务。

## 数据和能力边界

- `index.html` 内嵌全部 CSS / JavaScript；数据仅保存于当前浏览器的 `development-6-port-v1`。不同浏览器、不同端口或域名不共享数据。
- 面向单标签页操作，不提供多人协同或多标签页并发冲突协调。清除浏览器存储会丢失修改；CSV 为导出用途，无导入恢复功能。
- 只模拟卸船入场，箱量以整数计；不实现出场、取消派发、设备维修、真实班次日历或权限管理。
- 长台账在手机中可横向滚动，整页在 390px 宽度无横向溢出。
- 存储读取或写入异常会显示提示，不宣称保存成功。
